BCMS95 LAB — INTEGRAÇÃO COM NEON E VERCEL (PROJETO JÁ EXISTENTE)

OBJETIVO
Atualizar SOMENTE o repositório do BCMS95 LAB — Conversor de Capacitância e Tapeboard.
Não alterar o projeto BCMS95 de Análise Estatística por Amostragem.

1) NO NEON
Abra o projeto Neon reservado ao LAB (não use o banco do BCMS95 de amostragem).
Vá em SQL Editor, copie e execute o conteúdo de db/schema.sql.
Confirme a tabela public.lab_workspace.
No menu Connect, selecione a branch e o banco corretos e copie a string PostgreSQL
(com o pooler ativo, se disponível). NÃO envie a string no ChatGPT nem cole no GitHub.

2) NO GITHUB
Abra o REPOSITÓRIO EXISTENTE do BCMS95 LAB e selecione a branch main.
Extraia o arquivo ZIP e envie os arquivos à RAIZ do repositório, preservando
as pastas api/auth, api/_lib e db (e seus arquivos dentro delas).
Se já existirem arquivos com o mesmo nome, substitua pelo conteúdo novo.
Não envie o ZIP fechado. Confirme a estrutura indicada abaixo:
  index.html
  package.json
  api/projects.js
  api/_lib/database.js
  api/_lib/security.js
  api/auth/login.js
  api/auth/logout.js
  api/auth/report.js
  api/auth/session.js
  db/schema.sql
  LEIA-ME_PUBLICACAO.txt

3) NA VERCEL
Abra o PROJETO JÁ EXISTENTE ligado a esse repositório.
Em Settings > Environment Variables, adicione para Production:
  DATABASE_URL       = string de conexão PostgreSQL do Neon do LAB
  LAB_MAIN_PASSWORD  = senha principal escolhida para o conversor
  LAB_REPORT_PASSWORD= senha adicional escolhida para o Relatório Tapeboard
  SESSION_SECRET     = segredo aleatório com pelo menos 32 caracteres
Não adicione estas senhas aos arquivos do GitHub. Não reutilize a chave do outro BCMS95.
Salve as variáveis e, em Deployments, confirme uma implantação gerada
pelo novo commit. Se as variáveis foram adicionadas após o commit, clique em Redeploy.

4) TESTES DE FUNCIONAMENTO
- Acessar a URL atual da aplicação; usar a senha principal.
- Criar projeto de teste, memorizar conversão e atualizar a página.
- Abrir outro navegador autorizado, entrar e verificar o mesmo projeto.
- Abrir Relatório Tapeboard e digitar a senha adicional.
- Adicionar observação e assinatura; atualizar e verificar persistência.
- Gerar PDF e Excel; conferir a composição dos dados.
- Se surgir conflito de revisão, exportar backup, atualizar e revisar antes de salvar.

CUIDADOS
* O SQL cria somente a tabela lab_workspace, sem apagar registros existentes.
* Em primeiro acesso, se o banco estiver vazio e o navegador tiver projetos
  antigos locais, a aplicação oferece importar esses dados para Neon.
* Projeto único compartilhado: qualquer pessoa com a senha principal pode editar
  conversões e dados básicos dos projetos. A senha adicional protege a leitura
  e escrita das observações manuais e assinaturas na API.
* A segunda senha é um controle de acesso, não uma assinatura digital certificada.
* A versão usa autenticação por sessão em cookie seguro e HTTP-only.
* O app depende de conexão online para salvar e recuperar projetos.
